# Guitar shape table changes, 2026-11-27

Scope: first shapes (the grip `resolveChord` picks with no previous chord) for the 40 non-alias qualities × 12 roots = 480 cases. Only this folder changed. The app repo was not touched.

## What changed

- `shapes-lib.mjs`: 93 curated per-root grips added at the end of `OPEN_SHAPES`, under the heading "2026-11-27". Curated grips rank ahead of movable templates, so each one becomes the first shape for its chord. No movable template was removed or edited, so every older shape is still listed as an alternate after the new first shape. The only template change is a corrected comment: the A-shape Hendrix 7#9, `x(R)(R-1)(R)(R+1)x`, does fit in 4 frets.
- `shapes.json`, `TABLE.md`, `verify-output.txt` and `SHA256SUMS` were regenerated by `node verify.mjs`.
- Backups of the previous files: `shapes.json.bak-2026-11-27` (sha256 `de5a9db2…69966e`), plus `shapes-lib.mjs`, `TABLE.md`, `verify-output.txt` and `SHA256SUMS`, each with the same `.bak-2026-11-27` suffix.
- New barres carry a `finger` field when a finger other than the index lays the barre, for example the ring-finger barre in C9 `x32333`.

This table's resolver counted 69 cases and the app counted 68. Mine also included D7sus2 and Am9b5, which come from fallback search. The app instead had Bbm9b5, which its generator built as `636620` (5 frets). All of them are fixed, and a curated Bbm9b5 was added so the app has a library grip for it.

The new grips also changed some synthetic slash chords (every quality over every bass note), because the upper chord they are built from changed. Of 5,206 resolved slash chords, the number spanning more than 4 frets went from 1,531 to 1,426, and the number starting above fret 7 went from 850 to 797. None newly fail.

## Unresolved

- **Ebm13** stays `(11)x(11)(11)(13)(13)`, which starts at fret 11 and spans 3 frets. No open string is a chord tone of Ebm13 (Eb Gb Bb Db F C), so every sounding note has to be fretted. The checks require Eb, Gb, Db, F and C, which takes five strings. Rooted on the A string at fret 6, there is no way to place Gb, Db, F and C on the D, G, B and E strings within 4 frets. Rooted on the D string at fret 1, only three strings are left. The lowest legal 4-fret grip is `(11)8(11)(11)x8`, which starts at fret 8 (still above 7) and mutes the B string between sounding strings. I left the existing E-shape first rather than swap one grip above fret 7 for another, harder one.

## Note for the app port (Crash)

The app's `keepGrip` merges a curated grip with an identical movable-template instance. The merged grip takes the template's position and `from: "movable"`, so it loses its open-first priority. On my first pass, ten of the new grips were identical to E-shape template instances: Bb/B add9 `6x8768`/`7x9879`, Bb/B madd9 `688668`/`799779`, Bb9 `686768`, Bb/B maj9 `6x7768`/`7x8879`, Bbm9 `686668`, Bbm(maj9) `687668` and Bbm6/9 `6x8688`. The app then still put the 5-fret A-shape first. I replaced all of them with grips that match no template instance, so this table ranks the same in both resolvers as long as the new `openShapes` entries are ported as written. The older E-shape grips are still available as alternates.

## Shape families used

- 9: C9 grip `x(R)(R-1)RRR` for C–Eb and B; Bb9 uses the E-root `6x6768`.
- m9: `x(R)(R-2)RRx` (Dm9 `x5355x`); Bm9 is open `x20222`; Bbm9 is `6x6668`.
- maj9: `x(R)(R-1)(R+1)(R)x` (Cmaj9 `x3243x` family): Db `x4354x`, D `x5465x`, Eb `x6576x`, Bb `x1021x`, B `x2132x`.
- m(maj9): `x(R)(R-2)(R+1)(R)x`; B is open `x20322`; Bb is `6x7668`.
- 6/9: `x(R)(R-1)(R-1)RR` (C6/9 `x32233`). m6/9: `x(R)(R-2)(R-1)(R)x`; B is `x20122`; Bb is `xx8688`.
- 9sus4: one-finger barre `x(R)(R)(R)(R)(R)` (C9sus4 `x33333`).
- sus4add9: `x(R)(R-3)(R-3)(R-2)(R-2)` for C–Eb (C `x30011`); D-root `xx(R)(R)(R-2)(R)` for F–Ab; `x(R)(R)(R+2)(R)(R)` for Bb and B.
- madd9: Cm(add9) `x31033`, then `x(R)(R-2)(R-3)(R)x` for Db–Eb; Bb is `xx8668`; B is `x20422`.
- add9: Db `x41121`, Eb `x63343`, Bb and B on the D-root form `xx8768`/`xx9879`.
- sus2: Fsus2 `xx3011` and its D-root family for F# and Ab; Gsus2 is `300033`.
- 13: `x(R)(R-1)(R)(R)(R+2)` (C13 `x32335`). m13: C `x30345`, Db `x41300`, D `x53500`.
- 7#9: Hendrix `x(R)(R-1)(R)(R+1)x`. dimAdd9: `x(R)(R-2)x(R)(R-1)` (an inner mute, as the existing dimAdd9 template already has). dim(maj7): `x(R)(R+1)(R+1)(R+1)x`.
- maj7sus2 (F–Ab): `xx(R)(R-3)(R-2)(R-3)` (Fmaj7sus2 `xx3010`).
- One-offs: D7sus2 `xx0210`; m9b5: D `x56560`, Eb `x64665`, A `x01413`, Bb `63665x`.

Inner mutes appear only in qualities whose existing templates already mute an inner string (9, m9, maj9, m(maj9), dimAdd9).
